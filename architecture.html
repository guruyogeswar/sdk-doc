Architecture

LIMBIC is built on a strict separation: pools own data, modules own logic, the orchestrator owns the schedule. This document explains the three API layers, the seven-stage tick pipeline, and the data model that lets one machine run thousands of cognitive agents in real time.

Three layers

The host game touches Layer 2 (C++) or Layer 3 (C). The core stays sealed.

LayerSurfaceResponsibility
3limbic.h · C FFIStable C ABI — used by the Python, C#, Godot, and Unity bindings.
2LimbicEngine · C++ classPrimary integration. Move-only RAII handle. spawn, perceive, tick, get_decision, report_outcome.
1coreThe brain itself. Sealed. Consumers receive only the compiled shared library.

The seven-stage pipeline

Every tick, every agent, always in this order.

Sense
Percept world → 128-D vector
Feel
Amygdala, hypothalamus, interoception
Remember
Hippocampus encode + retrieve
Attend
ACC conflict + attentional dynamics
Decide
Basal ganglia D1/D2 + PFC bias
Act
Action execution + expression
Learn
Dopamine RPE + plasticity
Rule Fix perception or rewards — never hardcode behaviour. If an agent does the wrong thing, the diagnosis is upstream of the basal ganglia: bad percepts, bad reward shaping, or a misaligned neuromodulator baseline.

Data model: structure of arrays

Every per-agent field lives in a pool — a flat std::vector indexed by agent id. A module reads one or two pool fields and writes one or two pool fields. There are no agent objects. 

Inside a module C++// Cache-friendly, OpenMP-friendly, serialisation-friendly.
for (uint32_t i = 0; i < N; ++i) {
    emo.valence[i] += dt * (drive[i] - emo.valence[i]);
}

This layout gives three properties for free:

  • Cache locality. A module's hot loop walks one contiguous array.
  • Parallelism. #pragma omp parallel for over agent ids is safe and trivial.
  • Serialisation. A pool is its arrays plus a header — saving means dumping bytes.

Module discipline

Presets, not feature flags

Three presets — REACTIVE, COGNITIVE, FULL — control which modules run on a given agent.

Deterministic by seed

Same seed and inputs produce bit-identical output. Tests, replays, and emergent stories all reproduce.

Explainable

Every decision exposes its evidence via explain() — per-module contribution, neuromodulator state, action scores.

LOD-friendly

tick_agents() lets you tick only the agents that matter this frame, mixing presets in one world.

How a tick flows

  1. The host calls perceive() any number of times to push world state into each agent's sensory buffer.
  2. The host calls tick(dt). The orchestrator runs every enabled module in pipeline order, parallelising the inner agent loop with OpenMP.
  3. The basal ganglia commits a single action per agent into the decision pool.
  4. The host calls get_decision() and acts in the game world.
  5. The host calls report_outcome() with reward and energy delta. This populates the dopamine signal that the next tick's learning stage will consume.

Threading model

LimbicEngine is not thread-safe at the public API. Internally, tick() uses OpenMP across agents within each module. Specific rules:

OperationRule
tick(), tick_agents()Single thread. Do not call concurrently with anything.
Read-only queries (get_emotions, …)Concurrent with each other OK. Not during tick().
set_param, perceive, report_outcomeSingle thread. Call between ticks.
